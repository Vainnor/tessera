# Tauri Rules (not loaded at startup; read in full before touching the shell, capabilities or `tauri.conf.json`)

The checklist is `security.md` → "Webview and IPC". This file is how the shell is built.

## Shape

- `src/lib.rs` builds the app; `src/commands.rs` holds `#[tauri::command]` functions, each a few
  lines that call `tessera-core` and map errors to a serializable error type.
- **A new command touches four places**: the function in `commands.rs`, `generate_handler!` in
  `lib.rs`, `AppManifest::commands` in `build.rs`, and `allow-<name>` in `capabilities/main.json`.
  Miss one and the command is unreachable or ungated. Commit the regenerated
  `permissions/autogenerated/<name>.toml` with it. Mirror the return type in
  `apps/desktop/src/lib/types.ts` and add the wrapper to `src/lib/ipc.ts`.
- Plugins controlled from Rust get no JS permission. Adding any plugin is a dependency decision
  (`dependencies.md`) and a threat-model edit.

## Config

- `app.security.csp` is security config (`security.md`); `freezePrototype: true`,
  `withGlobalTauri: false`, no `dangerousRemoteDomainIpcAccess`, no `assetProtocol` scope, no
  `remote.urls` in any capability.
- The bundle identifier is `com.vainnor.tessera`. Changing it orphans every user's settings.
- `devUrl` (`127.0.0.1:5173`) must match `apps/desktop/vite.config.ts`.

## Per-OS

- **Linux** needs `libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev` and `librsvg2-dev` to build.
- **macOS**: unsigned builds trip Gatekeeper; signing and notarization are not set up yet.
- **Windows**: WebView2 is bootstrapped by the installer. `windows_subsystem = "windows"` in
  release so no console opens.
